# 動作検証と比較実験

研究対象はScene Tokenの構成と音響制御への利用。初期実装はルールに従って観測と制御が動くか、処理負荷が許容できるかを確認する。新規性や明瞭性改善は未確定。

## Phase 4の確認

1. BasicAudioTestを再生。生成音の距離・方向、壁の移動によるocclusionを確認する。
2. SceneTokenTestでsourceIdと8項目のToken、CSVのraw位置と一致するか確認。頭部/音源を移動し方向座標を確認する。
3. AdaptiveAudioTestでpriority=0.2 / 0.7 / 1、壁あり/なし、各taskPhase、期限なし/10秒以内を組み合わせ、3方式を切り替える。
4. 同じTokenの計算比較はEditModeテストで検証。ライブ聴取では配置・音量・同じ参照信号を固定し、方式順序を釣り合わせる。
5. controlEnabledをOFF、manager/rendererを無効化し、元のvolumeと既存LPF状態が戻ることを確認する。
6. ログファイルがUTF-8 CSVとして開け、IDの引用符・数値・目標値・平滑化中の適用値が区別できることを確認する。
7. Quest 3では頭部回転、左右手追跡、スティック移動、ボタンによる方式/重要度/壁切替、音響出力を確認する。Editor成功と別の結果として保存する。

NetworkAudioTestはPhase 5用のローカル足場であり、Photon接続/音声通信試験にはまだ使えない。

## 性能測定

20Hzを基準に音源1/4/8個、壁ありなしでcollection/control/total/frameのms分布を記録する。EditorとQuestで別々に中央値・95パーセンタイル・最大値と、実際の記録timestamp差分を確認する。負荷が大きい場合はupdateHzを下げ、条件・実測間隔を記録する。
CSVのtotal_msはDSP処理やCSV I/Oを含まない。実オーディオ負荷・GC・描画負荷はUnity Profilerで別途測る。

## 将来の音響評価

STI、SNR、定位誤差は現時点では未実装。校正した参照音・ノイズ、音量、マイク/録音経路、部屋/ヘッドフォン、被験者の回答方法・基準条件を設計してから導入する。
生成トーンは配線とフィルタ変化の確認用であり、人の音声を理解しやすくなったことの検証には使わない。gain/LPFのログだけから明瞭性や作業効率の改善を結論しない。
