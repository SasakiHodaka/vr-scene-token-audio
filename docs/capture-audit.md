# 取得ログの検査と独立注釈

実機を使わずに検査・集計を準備するための手順。現在、人間の実操作ログは未取得であり、以下は実測結果ではない。

## 取得したら最初に実行する

UnityのPlayを停止して書き込みを閉じた後、Game画面に表示された保存先を渡す。

```powershell
python Tools/audit_assembly_capture.py '取得フォルダーの絶対パス' --output 'Logs/capture-audit/初回検査'
```

Python標準ライブラリだけを使用する。入力フォルダーを変更しない。出力先は新しいフォルダーに限定し、取得フォルダー内への出力と既存注釈の上書きを拒否する。終了コード0はファイル整合性の検査成功、1は不整合、2は入出力・引数エラー。

出力するもの：

- `audit.json`：入力4ファイルのSHA256、イベント数、CSV行数、初期スナップショット数、音響文脈の有無・取得元、不整合と注意事項。
- `annotations.csv`：記録イベントに対する照合表。記録側イベントID・種別だけを記入し、期待値・根拠・担当者は空欄、状態はunreviewed。正解データではない。

## 検査すること

- capture-info、元観測、CSV、送信側フレームの共通IDと対応。
- イベントIDの重複、連続番号の欠落、時刻の逆転・非有限数。
- 各観測につき音響文脈数と同じCSV行数。文脈なしなら空欄の1行。
- 対象物座標、音響Tokenの値、作業者と音源の対応、姿勢から算出した距離。
- 送信側フレームの3関係（object/target/attempt）の参照・主体・時刻・値。

再開・一時停止後は新規フォルダーの最初のsequenceが1とは限らないため、ファイル内の連続性を確認する。複数端末の時刻は結合・比較しない。
フィールド比較の数値許容差はJSONに保存されたfloatの丸めを扱うための値（相対2e-6、絶対1e-6）。位置精度・時間精度の実験基準ではない。

## 検査で確定できないこと

同じ誤りが全ファイルへ記録されれば整合検査を通る。人間の実操作、操作の欠落、真の操作者・意図、SDK通知の意味、時刻同期、音声取得成功は独立に確認する。
`tracked_head_pose`は頭の位置であり実音声ではない。CSV行数は操作回数ではない。`*_snapshot`は接続時点の状態であり、その時点で操作が発生した証拠ではない。
actor_id=unknownは取付通知などでは正当な欠測である。直前の把持者を正解として補完しない。
現在のsender-framesは取得観測の一部を射影したもので、taskIdや全音響文脈を復元する完全な表現ではない。

## 独立した注釈

1. ログの前に、録画などの別根拠から[独立操作表](../Evaluation/templates/independent-operations.csv)を記入する。ログにない操作も行として残す。記録から作った照合表だけでは欠落を採点できない。
2. evidence_refは録画ファイルと該当区間など、第三者がたどれる参照を記入する。実験で録画を用いる際は必要な同意手続きを済ませる。
3. actor/object/targetは観測できる範囲だけ記入し、不明はunknown、適用外はnot_applicable。observabilityと理由を残す。
4. 次にannotations.csvで記録イベントとの対応を照合する。期待値を記録出力からコピーしない。時刻対応が確認できる前に自動的な最近傍マッチングをしない。
5. 不一致、記録の欠落、余分な通知、識別不能を別々に集計する。人の操作一つに両端や複数端末の通知が対応する可能性があるため、行数で採点しない。
6. 評価に使用する正解はレビュー根拠を残して別途確定する。未レビュー行は評価精度の分母に混ぜない。

この作業は取得品質の評価であり、Scene Token構成の優位性を示す比較とは分ける。
