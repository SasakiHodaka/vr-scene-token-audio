# 研究成立条件の検討書

状態：研究課題の方向性は承認、仕様確定は保留。C1〜C3の実装には進まない。
本書は比較実験に進むための検討案であり、優位性・新規性・実験結果を報告するものではない。
過去の仕様案と異なる場合は本書の検討状態を優先する。

## 1. 研究課題・対象

研究テーマ「VR遠隔協調作業（意味的空間音声・通信手法）のためのScene Tokenの構成」を維持する。

研究課題：VR協調作業の意味的な状況を再現するため、発話・操作・対象物・工程の間のどの関係を、どの更新単位・時間表現で保持すべきかを明らかにする。

意味的再現とは、例えば「BがM1をSlot1へ取り付け、その操作が指示U1に対応する」「Assemblyは未完了」のような事実・関係を復元すること。
形状・音声波形・細かな軌跡を含むVR空間全体の再現、受信者選択、AI判断、作業効率の改善は今回の対象外。
固定規則による工程推定は扱えるが、観測された完了と推定された完了を区別する。

必要性の候補は、並行操作・同種部品・時間差のもとで、誰のどの操作と発話が対応するかを取り違えずに復元すること。
ただし、これは情報管理上の要求であり、既存ログやScene Graphでは解けないことを意味しない。

## 2. 競合仮説と反証条件

- H0：共通ID・時刻を持つ構造化ログで、必要な作業関係・状態を十分に復元できる。
- H1：同じ観測情報と知識を使って関係を明示する構成が、特定条件で高い関係再現または低い総処理負荷を実現する。

現段階のH0/H1は研究上の作業仮説。統計的検定の帰無仮説・対立仮説として形式化したものではない。
「十分」の精度下限・遅延上限、意味のある改善幅・負荷低下幅は未確定。対象作業の要求または予備測定から根拠を示し、本評価前に固定する。
数値が未確定のまま、優位性・同等性を判定しない。

反証・見直し条件：

- 正しいIDと相関IDを持つ既存ログで同じ関係を復元できるなら、関係明示による情報上の優位性は主張しない。
- 明示関係が同一情報の決定的な変換なら、精度差は必然ではない。検索・結合コストの事前計算とデータ冗長性のトレードオフとして評価する。
- 明示方式だけが正解の対応関係を外部から与えられるなら、表現方法の比較として無効。その結果は追加観測情報の効果として分ける。
- 差がない場合、検証条件下では既存方式で十分だったと報告する。有意差がないことだけで統計的同等性を結論しない。
- 期待する差が得られなければ、更新単位・時間表現・反復問い合わせ頻度に検討を移す。情報を減らして比較相手を意図的に不利にしない。

## 3. 比較方式：まず関係表現を検討

共通の観測集合Oと事前知識Kを定義し、全方式へ同一のO・Kを渡す。
Oは作業者ID、対象物ID、イベントID、操作開始・結果、発話、観測時刻等。Kは事前定義した工程規則・依存関係等で、実行後の正解状態を含まない。
共通IDを持つ別JSONにも関係は存在する。「分離」と「関係なし」を同一視しない。

| 方式候補 | 保存・復元方法 | 公平性の条件 |
|---|---|---|
| L：構造化ログ | 型別のレコードに共通ID・時刻を保存。必要な索引・結合を使用 | 相関IDが観測されるなら省かない。単純な最近傍時刻照合に限定しない |
| R：明示的な関係 | 同じO・Kから作業者→操作→対象物、発話→操作等の関係を事前計算して記録 | 関係生成の処理・保存量・更新コストも計上。推定不能ならunknown |
| G：動的Scene Graphに基づく基準方式 | L/Rと同じ実体・関係・時刻をノード／エッジで表現 | 具体的な採用方式・更新方法・文献との差を事前に定義。任意のグラフ実装を既存論文の再現と称さない |

LとRを第一段階の最小比較にする。Gの具体化は仕様承認前の課題であり、未実施のままScene Graphより優れるとは主張しない。
RはScene Token候補であり、単に関係を保存するだけで新規性があるとはしない。

### 観測可能性の区別

観測に発話U1と操作E1の明示的な相関IDがある場合、L/Rの両方に与える。
相関IDがなく、同じ作業者・同種部品・時間だけでは対応を一意に決められない場合、どちらもその対応を確定できない。
正解データが関係を知っていても、その知識をRの入力へ流用しない。
この場合の正しい振る舞いはunknownまたは曖昧な候補集合であり、推測で正解を当てることを要求しない。

本評価では、観測から一意に識別可能な関係と、本質的に識別不能な関係を事前に分類する。
識別可能な関係の再現と、識別不能な関係に対する誤断定の抑制を別に評価する。

### 共通知識条件

- Kなし：全方式とも工程の意味的規則を与えない。
- Kあり：全方式に同じ版の工程規則を与える。

同じK条件内でL/Rを比較し、Kの有無は別要因とする。
「M1取付成功で工程完了」という規則が実作業の定義と一致するなら全方式で使用可能。
別の検査が必要なら、その検査まで完了しない限り工程完了にはならない。
旧仕様のC2だけに工程推定を禁止する規則は採用しない。

## 4. 時間表現・Token単位：第二段階

| 候補 | 保持するもの | 主な問い |
|---|---|---|
| T1 固定間隔状態 | 観測済みの現在状態を周期的に保存 | 区間内の短い変化・順序が失われる条件は何か |
| T2 イベント単位 | 発生時刻付きイベント＋共通初期状態 | イベント列から継続状態を正しく復元できるか |
| T3 状態＋イベント | 状態更新と発生時刻付きイベント | 再構成負荷の低下に対する追加量・整合管理コストはどれだけか |

全方式の元観測と時刻精度を固定する。イベント発生時刻と受信・利用可能時刻を分離し、オンライン評価で未来情報を使わない。
T1が区間内イベントを失うなら、それは出力表現の情報損失である。情報を同量保持した構成比較と混同しない。
同じ配信時点での比較と、イベント即時送信など実用設定の比較を分け、更新頻度による差を明記する。
イベント時刻の量子化、配信周期、履歴保持期間は別パラメータとし、同時に変更しない。

1 Tokenの単位は未確定。候補は「イベント＋関係参照」または「区間の状態＋イベント」。
Tokenという単位を設ける理由の候補は、更新対象・時間範囲・関係参照・重複排除を受け手が一意に解釈するための契約である。
既存のイベントエンベロープ等でも実現可能であり、名称固有の必要性は主張しない。
誤対応、更新量、復元遅延、処理コストの比較から単位を選び、選択理由がなければ既存形式を採用する。

## 5. まず確認する3条件

従来の「指示・操作・引き継ぎ」は業務場面の分類として維持する。以下はそれらに適用する難しさの条件であり、別の分類軸。

| 条件 | 操作・発話の例 | 検証・対照 |
|---|---|---|
| S 単純 | BがM1を操作する | Lでも十分に復元できる対照。提案側が不必要な負荷を増やさないか |
| P 並行 | B/Cが同種のM1/M2を同時に操作する | 個体IDと相関IDがあれば解ける場合、時刻・種類だけでは識別不能な場合を対にする |
| D 時間差 | 指示後、別操作を挟んで対象操作が発生する | 時間差だけでは既存ログの限界にならない。明示ID・履歴・共通知識で解ける条件と解けない条件を分ける |

イベント順序・役割・部品ID・時間差を変えた反復例を用意し、特定IDや固定時刻への実装依存を避ける。
失敗・再試行、指示対象と操作対象の不一致、遅延到着は次の拡張条件。正常系の取付成功を工程完了と同一視しない。
具体的な条件ごとの入力と正解は未作成であり、既存正常系JSONをこれらの評価データとして扱わない。

## 6. 独立した正解と評価方法

正解はシナリオ設計時に人手で作成し、各関係をevent_id等で特定する。全方式の出力から独立させる。
正解と別に、各関係について入力O・Kからの識別可能性と根拠を記録する。
復元結果は「主体、操作、対象物、必要な取付先、時刻区間、必要なら発話参照」のタプルに正規化する。必須要素と許容時間差は評価前に固定する。
同じ正解への多重マッチは認めない。余分な関係・重複はFP、欠落はFN。対応付けは一対一とする。

| 指標 | 定義 |
|---|---|
| 関係再現 | 識別可能な正解についてprecision=TP/(TP+FP)、recall=TP/(TP+FN)、F1。主体・対象・時刻等の必須要素がそろって正しいものだけTP |
| 誤対応 | 断定した関係のうち主体・対象・発話参照を誤った件数／断定件数。時刻だけの誤差も別報告。0件断定時はN/Aで、成功としない |
| 曖昧性への対応 | 識別不能なケースで断定した誤り、unknown率、候補集合を出す場合の集合サイズと正解包含率を別報告 |
| 状態再現 | 同じチェックポイントで操作・取付・工程状態を照合。直接取得と規則による導出を区別し、未復元率も示す |
| データ量 | 同一形式・同一時間範囲の実バイト数。初期状態・ID辞書・エッジ・索引・スナップショットを計上し、通信量と保存量を区別 |
| 処理負荷 | 収集、関係生成・索引更新、符号化、復元・検索、I/Oを分離。関係の事前計算を除外して復元側だけを比べない |
| 遅延 | 発生→利用可能、利用可能→表現更新、更新→問い合わせ回答を分ける。CPU時間と配信待ちを混同しない |

問い合わせ回数・内容・履歴長を固定し、単回復元と反復検索を別条件にする。再現精度、総コスト、更新遅延のトレードオフを示す。
空の分母はN/A、観測可能な正解があるのにunknownしか出さない方式はrecallが低くなるようにする。
各条件の結果を提示し、条件を混ぜた平均だけで優位性を結論しない。実行反復と独立したシナリオ数を区別し、統計計画は本評価前に定める。
